# Ядра LeksOS

Форк стабильного ядра Linux для LeksOS. Здесь собираются пять ядер:

| Пакет | Ветка | Для кого | Чем отличается |
|---|---|---|---|
| `linux-leksos` | `leksos/7.3` | работа, учёба, ноутбуки | 300 Гц, вытеснение full, крупные страницы памяти (THP) по запросу |
| `linux-leksos-game` | `leksos/7.3` | игры | 1000 Гц, THP всегда, планировщик scx_lavd и без замедления split lock (две службы, работают только под этим ядром) |
| `linux-leksos-server` | `leksos/7.3` | серверы | 250 Гц, вытеснение lazy, BBR и fq; без звука, Bluetooth, камер, ТВ-тюнеров и геймпадов; усиленная защита памяти ядра |
| `linux-leksos-rt` | `leksos/7.3` | запись звука, станки, роботы | PREEMPT_RT, 1000 Гц; без THP и i915 (их выключает сам PREEMPT_RT) |
| `linux-leksos-lts` | `leksos/6.18` | запасное | как обычное, но на ветке с долгой поддержкой |

Общее для всех: имя `leksos`, `/proc/config.gz`, пространства имён
пользователя (для lks), BPF и сменные планировщики sched_ext, MGLRU, zram и
zswap, NTSYNC (Wine и Proton), Rust, сжатие zstd, подписанные модули, все
драйверы модулями. Защита от уязвимостей процессора включена; выключить её
можно параметром загрузки `mitigations=off`. Вытеснение меняется при
загрузке: `preempt=full` или `preempt=lazy`.

`uname -r` выглядит так: `7.3.1-1-leksos`, `7.3.1-1-leksos-game`,
`6.18.60-1-leksos-lts`.

## Как всё устроено

- **`main`** (эта ветка) — сборка: `PKGBUILD`, проверка настроек
  `check-config`, службы игрового ядра, скрипты GitHub Actions в `ci/` и
  `tools/leksos-kernel-publish` для вашего компьютера.
- **`leksos/7.3`, `leksos/6.18`** — ядро: стабильная версия с kernel.org и
  поверх неё коммиты LeksOS. Настройки лежат в самом ядре:
  - `arch/x86/configs/leksos_defconfig` — основа;
  - `kernel/configs/leksos.config` — общее для всех видов;
  - `kernel/configs/leksos-<вид>.config` — добавка вида ядра.
- **Метки** `v7.3.1-leksos1`, `v7.3.1-leksos2`… — из них собираются пакеты.
  Номер после `leksos` — номер сборки, он же `pkgrel`.

Настройки собираются командой
`make leksos_defconfig leksos.config leksos-<вид>.config`, а потом
`check-config` проверяет, что ядро приняло каждую строку добавок. Если опция
переименована или не прошла по зависимостям, сборка останавливается и
показывает её.

## Сборка в GitHub Actions

Каждый день в 04:23 по Москве workflow «Ядра LeksOS»:

1. Смотрит в [gregkh/linux](https://github.com/gregkh/linux), вышел ли новый
   выпуск 7.3.x или 6.18.x. Если вышел — переносит коммиты LeksOS на него
   (rebase) и ставит метку `v<версия>-leksos1`. Если в ветке `leksos/*`
   появились ваши коммиты — ставит метку со следующим номером.
2. Собирает нужные виды ядра параллельно, в контейнере Arch.
3. Запускает каждое ядро в QEMU: оно должно загрузиться до своей программы
   init. Иначе пакет никуда не попадает.
4. Выкладывает пакеты и их суммы в релиз GitHub с именем метки.

Запустить вручную: вкладка **Actions** → **Ядра LeksOS** → **Run workflow**:

- **проверить** — то же, что по расписанию;
- **собрать** — собрать текущие метки как есть (первый раз или после сбоя);
- **пересобрать** — новая метка без изменений в ядре (например, после правки
  `PKGBUILD`).

Если перенос на новый выпуск даёт конфликт, workflow останавливается с
ошибкой, и GitHub присылает письмо: перенесите ветку сами
(`git rebase --onto v7.3.2 v7.3.1 leksos/7.3`) и отправьте её.

### Первый запуск

1. **Settings → General → Default branch** — выберите `main`. Расписание
   GitHub запускает только из ветки по умолчанию.
2. Вкладка **Actions** — в форках она выключена, нажмите кнопку, которая
   включает workflows.
3. **Actions → Ядра LeksOS → Run workflow → проверить.** Первый запуск
   сам поставит метки `v7.3.1-leksos1` и `v6.18.60-leksos1` на вершины
   веток `leksos/*` и соберёт все пять ядер.

Сборка одного ядра идёт примерно 1–2 часа. Если в репозитории 60 дней ничего
не происходит, GitHub выключает расписание — включается там же, в Actions.

## В репозиторий [leksos]

Пакеты в релизах не подписаны. Подписываете их вы, на своём компьютере,
своим ключом — он никуда не уходит:

```
tools/leksos-kernel-publish            # все пять ядер
tools/leksos-kernel-publish game lts   # только эти
```

Скрипт берёт метки из `PKGBUILD` этой ветки, скачивает пакеты из релизов,
сверяет суммы, подписывает, добавляет в `leksos.db` (`repo-add --sign -R`) и
выкладывает репозиторий на сервер. Настройки — в
`~/.config/leksos/publish.conf`:

```
LEKSOS_KEY=отпечаток вашего ключа
LEKSOS_REPO=~/repo/x86_64
LEKSOS_RSYNC=user@server:/путь/к/репозиторию/x86_64/
```

Пока ключа нет, `LEKSOS_KEY` можно не задавать: пакеты попадут в репозиторий
без подписи. Так можно только пока у `[leksos]` стоит `SigLevel = Optional`.

## Собрать у себя

```
LEKSOS_FLAVOR=game makepkg -s          # из метки на GitHub
LEKSOS_TREE=~/linux makepkg -s         # из своего дерева, с несохранёнными правками
```

Без `LEKSOS_FLAVOR` собирается обычное ядро. Полная сборка на старом
процессоре занимает несколько часов.

После правки `check-config` или служб игрового ядра обновите суммы в
`PKGBUILD`: `updpkgsums` (из пакета `pacman-contrib`).

## Правки ядра

Коммитьте в `leksos/7.3`. Если правка нужна и запасному ядру — ещё и в
`leksos/6.18`. Утренний запуск сам поставит новую метку и соберёт ядра.

Настройки меняются в `kernel/configs/leksos*.config`. Проверить перед
коммитом:

```
make O=/tmp/k leksos_defconfig leksos.config leksos-game.config
./check-config /tmp/k/.config kernel/configs/leksos.config kernel/configs/leksos-game.config
```

## Новая версия ядра (например, 7.4)

Переход на новую серию делается руками: в ней появляются новые опции.

```
cd ~/linux
git fetch https://github.com/gregkh/linux tag v7.4
git switch -c leksos/7.4 v7.4
git cherry-pick v7.3.1..leksos/7.3        # коммиты LeksOS (от базы текущей метки)
~/linux-main/ci/new-options ~/linux       # под ядром linux-leksos
git commit -am 'leksos: настройки для 7.4'
git push origin leksos/7.4
```

Здесь `~/linux-main` — клон ветки `main`. `ci/new-options` берёт настройки
работающего ядра, включает новые драйверы модулями, записывает
`leksos_defconfig` и проверяет все виды ядра. Потом в `main` поменяйте в
`PKGBUILD` `_stable=7.4` и `_stable_rev=1` и запустите workflow →
**проверить**: он сам поставит метку `v7.4-leksos1` и соберёт ядра.
Запасное ядро переходит на новую LTS так же, через `_lts` и `_lts_rev`.

## Что нужно знать

- **zfs-dkms 2.4.4** поддерживает ядра до 7.2, поэтому для 7.3 он не
  соберётся. С ZFS используйте `linux-leksos-lts`, пока не выйдет zfs с
  поддержкой 7.3.
- **VirtualBox** на этих ядрах — через `virtualbox-host-dkms` и пакет
  заголовков нужного ядра (`linux-leksos-headers` и т. д.).
- **Secure Boot**: ядра не подписаны ключом Microsoft — выключите Secure
  Boot или подпишите ядро сами (sbctl).
- **Игровое ядро**: планировщик scx_lavd включается, если установлен
  `scx-scheds`. Свой планировщик — `sudo systemctl mask leksos-game-scx`.
